## F. Critical context & nuances (do not lose)
- **THE BEHAVIOURAL THESIS (most important nuance in this file).** The original assumption — "seeing tasks stack up creates healthy urgency" — is **wrong for this audience** and was corrected in round 5. ADHD brains steeply discount the future (so the moving now-line is genuinely well-aimed at time blindness), but accumulated visual debt produces **task-initiation paralysis**: lists flatten importance so everything reads urgent and nothing does; the planning load *precedes* action and is the real barrier; each rollover adds emotional weight, not motivation. It's an inverted U — a little debt is salience, a lot is shutdown. **Never remove the overdue cap or the progress counterweights without re-reading this.** Sources are cited in `docs/APP_DESCRIPTION.md`.
- **Stickers deliberately break the design system.** `components/stickers/art.jsx` hard-codes its colours (lavender/mint/butter/sky/pink) *outside* the theme tokens so the characters stay equally warm in light and dark. That is intentional — do not "fix" them to use tokens. One character is hashed per day key so a pile keeps the same character.
- **`urgency: number | null` + `urgencyOff: boolean`.** `null` means unranked and must **never** be coerced to 0 — for sorting only, `bands.rankOf` falls back to a neutral 5 so unranked tasks interleave instead of sinking. The compressed input bar intentionally has **no** urgency control (quick capture stays quick → lands unranked, rankable later in `TaskEditor`).
- **Preview quirk (important for verification):** when the Browser pane is hidden, `requestAnimationFrame` freezes, so Framer Motion animations stall mid-flight and `AnimatePresence mode="wait"` never mounts the next view — the screen looks blank or dim. This is a harness artifact, **not** a bug. Take a screenshot to force a paint, verify via DOM evals, and use `npm run build` as the definitive correctness check. The console buffer for a tab also persists stale HMR errors across reloads and server restarts.
- **Coordinate space rule:** the now-line, gridlines, markers, timed bars, and elapsed fills must all measure against the **full day-column width** (no horizontal padding on the task container). This is why `px-1.5` was removed — any future inset must be applied consistently to all of them or it re-creates the blue-sliver bug.
- **Marker axis is imperative:** `MarkerAxis` in `Timeline.jsx` runs a continuous rAF reading `scroller.scrollLeft` + the `.js-chatbar` rect each frame. Spring lift state is keyed by **absolute tick index** in a `Map` (`springMap`), NOT by pool slot — keying by slot made the whole row's lift jump one tick every time the scroll window shifted. Do NOT revert to slot-indexed springs or to a scroll-only React-state model (that caused the frozen-marker bug).
- **Now-line:** `pointer-events:none` (so tasks stay clickable), glow via proximity mousemove, transition disabled on first ~700ms so it starts exactly on time.
- **Chat bar drag** is 100% ref-driven — **no `setState` during the gesture** (a re-render mid-drag reapplies the docked `left:50%/translateX(-50%)/bottom` style and clobbers the imperative pin → the old top-right teleport). It also uses a **5px movement threshold**: the bar only detaches/pins after the pointer actually moves, so a plain press near the border does nothing. Cursor is toggled imperatively (`cursor-moving` class). Edge-detection only arms when the pointer is *inside* the bar rect (points above/outside — like the open time popover, a DOM child — must NOT count as near-edge) and never from a `button/input`. Magnetizes home within ~70–90px of dock; on re-dock the imperative styles are cleared so React's docked style reasserts.
- **Timed-bar resize is cursor-based** (`TimedBar.jsx`, `onEdgeDown`): invisible `EDGE`-px hit-zones at each end swap the cursor to the thin `↔` (`.cursor-ew`, updated to include the connecting line); no visible handle. Imperative during the drag — mutate the bar's `left/width` + the delta pill directly each frame, commit `{start,end}` (**15-min snap**) via `store.updateTask` only on release; `layout={!dragging}` disables framer's layout animation during the gesture. The pill is portaled, fixed-height, single-line, shows the **signed duration delta**. **Gotcha:** the edge is rendered via a plain element-returning function (`renderEdge`), NOT a component defined inside render — an in-render component gets a new identity every render, so `setDragging` would remount it mid-drag and break pointer capture.
- **Timed-bar geometry & tiers:** uniform `BAR_H=44`, `LANE=56` (44 + 12 gap) — matches the cards' 44px height. `MIN_PX=42` min render width (fits chevron; circle joins ≥62px, clipped title+chevron ≥94px, full title when it measures to fit via a canvas `measureTitle`). `packLanes(timed, dayWidth)` packs by **effective width** (`max(trueSpan, MIN_PX-equivalent)`) so min-width bars never overlap their time-neighbours — keep `BAR_MIN_PX` in `Timeline.jsx` in sync with `MIN_PX`.
- **`elapsedFraction` / `elapsedToday`** live in `rollover.js`; only today-tasks tint; the tint is gated by `settings.overdueTint`; the "0 days overdue" coral is **independent** of that toggle.
- **Parked:** click-anywhere-to-add and the preview chips (`_parked/`, `PARKED_FEATURES.md`).
- **Preview quirk:** the preview tool sometimes returns a downscaled/dim screenshot right after `location.reload()` — re-resize to force a clean capture; trust DOM-evals over a single odd frame.
- **Dates in the running app** use the real browser clock (not a fixed 2026 date); seed data is anchored relative to "today."
